# 收纳托盘预览验证

本文记录迁入前的独立 `mac_stats_bar` 仓库；下文中的分支、路径和操作均属于当时环境。本次迁入结果见 [integration.md](../integration.md)。

日期：2026-09-15。分支：`feature/expandable-tray`。基线：`main` / `57f8079`。

## 构建与使用

```sh
./scripts/build.sh preview
open "dist/Mac Stats Bar Preview.app"
```

本分支无参数构建也默认使用 preview。应用标识为 `local.macstatsbar.preview`，构建产物、设置、菜单栏位置和辅助功能授权与 `local.macstatsbar.app` 分开。原有 `dist/Mac Stats Bar.app` 保留。

首轮预览版包体 1,676 KiB（约 1.64 MiB），本机 release 构建无编译警告，临时签名校验通过。原有初版包体仍为 1,088 KiB。

## 已实测

环境：macOS 15.1.1，Apple Silicon，14 核、48 GB 内存。

| 检查 | 结果 |
| --- | --- |
| 核心检查 | 23/23 通过：既有 18 项，加刘海/多屏/小屏/自动隐藏布局与顺序恢复 5 项 |
| 原生托盘 | 560 × 362 的紧凑面板；实际界面显示真实 CPU、内存、网络、Codex 额度和重置卡 |
| 辅助功能未授权 | 显示明确的连接入口，系统状态与额度仍可使用 |
| 菜单栏项发现 | 授权后发现 15 项；系统出现额外控制项后为 16 项，数量随当前运行状态变化 |
| 搜索 | 搜索 Mac Stats / 电池后只保留对应真实项 |
| 收起 | 分隔线收起开关生效；收起后刷新仍能发现上述菜单项 |
| 外部应用实际菜单 | 点击托盘中的旧版 Mac Stats Bar 项，打开该独立应用自己的原生面板；收起原图标后重复操作也成功 |
| 系统实际菜单 | 点击「电池」，打开 macOS 控制中心的电池面板 |
| 设置入口 | 从托盘齿轮进入偏好设置，显示托盘开关与小箭头开关 |
| 正常退出/重开 | 通过预览版退出按钮关闭后重开，分隔线整理状态结束 |

跨应用操作在首轮已授权构建上验证。随后构建调整图标的后台/主线程分工、关闭功能时的清理、休眠/屏幕变化处理，并为菜单栏容器补齐单次调用超时；没有更换菜单操作机制。重启时曾观察到辅助功能未授权，本轮修正版已完成重新绑定。

## 完成收纳流程修正

原「结束整理」会移除分隔线并恢复全部图标，与完成收纳的预期相反。现改为「完成并收起」：重新读取拖动后的图标位置，隐藏分隔线左侧的项目，并在托盘中只显示这批收纳项。「重新整理」用于调整范围，「停止收纳，恢复全部图标」独立放在更多菜单中。

- 修正版 release 构建无编译警告，签名校验通过，核心检查 23/23 通过。
- 用户授权重新绑定并完成 macOS 本地身份验证后，重新添加当前预览版；应用能读取到 15 个菜单栏项。
- 分隔线左侧没有项目时，点击「完成并收起」显示拖入图标的提示，保持整理状态。
- 完成实际整理后，界面显示「已收纳的图标 4」；页脚显示「原图标已隐藏」与「重新整理」。具体应用名单在迁入时省略。
- 用户随后确认已完成测试。保留当前预览版及收纳布局，关闭本轮临时启动的旧版应用。

本轮只修正完成收纳的流程，没有新增定时扫描；未重新测量资源占用。下节数据仍属于首轮预览构建。

## 短时资源测量

原始记录：[performance-tray-idle.json](performance-tray-idle.json)。首轮预览构建新启动、面板关闭、辅助功能尚未重新授权，系统 5 秒/额度 300 秒刷新。在 30.744 秒观察中：

- RSS：26.984–27.172 MiB。
- 平均 CPU：0.293%（单核口径）。
- 观察期间子进程数：0。

这是**尚未加载托盘图标的冷启动空闲状态**，不代表打开托盘、启用跨应用扫描或一次 Codex 查询时的占用；也不能和已经打开过界面的初版 70.5 MiB 直接比较。没有据此推断长时间耗电。

## 实现边界

- 使用公开 `AXExtrasMenuBar` / `AXPress` / `AXShowMenu` 接口发现和调用菜单。没有复制 Ice 的实现代码或引入第三方依赖。
- 托盘显示应用图标。一个应用提供多个系统项时可能出现相同图标，名称用于区分；它不是原始菜单栏图标的截屏复制。
- 原菜单由原应用定位。托盘在刘海下方，但本版没有把其他应用的弹出菜单重新定位到托盘下方。少数不提供辅助功能动作、退出或无响应的应用会无法操作，并显示失败提示。
- 外部菜单打开前恢复原图标，保持展开到用户下次关闭托盘，再按之前的收起选择恢复。没有在用户操作菜单的中途自动挤走原图标。
- 原菜单栏的排列由用户按住 ⌘ 拖动完成。右键的向前/向后移动只调整托盘内部顺序，保存在本地设置中。
- 整理时临时显示全部图标；「完成并收起」重新读取拖动后的图标位置，收纳分隔线左侧的项目并立即隐藏主栏图标。完成后托盘只显示这批收纳项。「停止收纳」是独立操作，不再作为完成整理的按钮。
- 关闭功能、停止收纳、退出、休眠或屏幕布局变化时移除分隔线并恢复原图标。整理模式不会在下次启动时自动开启。
- 只在展开、手动刷新或面板显示期间重新激活应用时扫描；隐藏时取消扫描，移除点击监听并释放 SwiftUI 面板。单次扫描使用总截止时间，逐应用/逐项检查取消，单次辅助功能调用有限超时。
- 无需录屏权限；不截取桌面、不读取其他应用的文档或聊天内容。辅助功能本身是 macOS 授予的广泛权限，因此通过明确的用户按钮连接。
